# 外部自瞄接入 AimSim 仿真程序说明

## 1. 文档目的

本文说明外部 RoboMaster 自瞄程序如何接入 `rm_aim_benchmark_sim` 独立仿真器。

接入完成后，外部自瞄程序可以：

- 接收仿真相机 JPEG 图像；
- 接收云台、相机、枪口和射击机器人位姿；
- 获取相机内参；
- 向仿真器发送绝对 `yaw / pitch` 云台目标角；
- 向仿真器发送 `fire` 开火建议；
- 在人工模式下配合“右键启用自瞄 + 左键允许开火”完成真实弹丸发射；
- 使用同一套物理碰撞系统统计 Shots、Hits、命中率、DPS、HP 和击杀时间；
- 在自动 Benchmark 模式下无人值守测试 Tracker、Predictor、Planner 和 Shooter。

本文以当前 `v0.2.0` 源码中的 `protocol.rs`、`network.rs`、`control.rs`、`camera.rs` 和 `telemetry.rs` 为准。

---

## 2. 总体数据流

```text
                    rm_aim_benchmark_sim
                           │
          ┌────────────────┼────────────────┐
          │                │                │
     Camera TCP       Telemetry UDP    Command UDP
     127.0.0.1:39002  → 39001          ← 39000
          │                │                ▲
          ▼                ▼                │
    ┌──────────────────────────────────────────┐
    │              外部自瞄程序                 │
    │                                          │
    │ Camera Receiver                          │
    │      ↓                                   │
    │ Detector                                 │
    │      ↓                                   │
    │ PnP / Reprojection                       │
    │      ↓                                   │
    │ Tracker / EKF / Factor Graph             │
    │      ↓                                   │
    │ Predictor                                │
    │      ↓                                   │
    │ Aimer / Planner / Shooter                │
    │      ↓                                   │
    │ yaw_deg / pitch_deg / fire               │
    └──────────────────────────────────────────┘
```

外部自瞄至少需要实现三条通信链：

1. TCP 接收相机图像；
2. UDP 接收遥测；
3. UDP 发送云台与开火命令。

## 3. 默认网络端口

默认配置位于：

```text
config/default.toml
```

网络配置：

```toml
[network]

# 外部自瞄 -> 仿真器
command_bind = "127.0.0.1:39000"

# 仿真器 -> 外部自瞄
telemetry_target = "127.0.0.1:39001"

# 仿真器 -> 外部自瞄
camera_bind = "127.0.0.1:39002"

telemetry_hz = 120.0
```

对应关系：

| 数据 | 方向 | 协议 | 默认端口 |
|---|---|---|---|
| 云台控制 / 开火建议 | 外部自瞄 → 仿真器 | UDP JSON | `39000` |
| 云台/相机/枪口位姿与统计 | 仿真器 → 外部自瞄 | UDP JSON | `39001` |
| 相机图像 | 仿真器 → 外部自瞄 | TCP 二进制帧 + JPEG | `39002` |

如果仿真器和自瞄程序运行在同一台 Windows/Linux 主机上，直接使用 `127.0.0.1` 即可。

如果运行在不同设备、WSL2、NUC 或局域网主机上，需要修改监听地址和目标 IP。

## 4. 外部自瞄发送云台命令

### 4.1 UDP 地址

仿真器默认监听：

```text
127.0.0.1:39000
```

外部自瞄向该地址持续发送 JSON 数据包。

### 4.2 数据格式

```json
{
  "yaw_deg": 12.5,
  "pitch_deg": -4.2,
  "fire": true
}
```

字段含义：

| 字段 | 类型 | 含义 |
|---|---|---|
| `yaw_deg` | float | 云台绝对 yaw 目标角，单位 ° |
| `pitch_deg` | float | 云台绝对 pitch 目标角，单位 ° |
| `fire` | bool | 自瞄是否建议当前时刻允许开火 |

这里的 `yaw_deg` 和 `pitch_deg` 是**绝对目标角**，不是角速度，也不是相对增量。

例如：

```json
{
  "yaw_deg": -18.25,
  "pitch_deg": 3.6,
  "fire": false
}
```

表示：

```text
目标 yaw   = -18.25°
目标 pitch = +3.60°
当前不建议开火
```

### 4.3 推荐发送频率

仿真器没有要求固定命令频率，但命令存在超时机制。

默认：

```toml
[operator]
command_timeout_s = 0.35
```

如果外部命令超过约 `350 ms` 没有更新：

```text
external_command_fresh = false
```

此时外部自瞄不能继续触发发射。

建议外部自瞄以 `50 ~ 200 Hz` 持续发送命令，常用可设为 `100 Hz`，即每 `10 ms` 发送一次最新的：

```text
yaw_deg
pitch_deg
fire
```

不要只在目标角发生变化时发送一次。

## 5. 人工模式下的自瞄接管逻辑

外部自瞄程序可以一直运行、一直发送命令，但人工模式下是否真正使用这些命令由操作手决定。

### 5.1 未按右键

```text
RMB 松开
    ↓
外部自瞄命令仍然接收
    ↓
但不接管云台
    ↓
鼠标控制 yaw / pitch
```

因此即使外部程序持续发送：

```json
{
  "yaw_deg": 30.0,
  "pitch_deg": -5.0,
  "fire": true
}
```

只要没有按住右键，外部自瞄不会抢走云台。

### 5.2 按住右键

```text
按住 RMB
    ↓
auto_aim_enabled = true
    ↓
如果 external_command_fresh = true
    ↓
外部 yaw_deg / pitch_deg
    ↓
成为云台目标角
```

此时鼠标不再直接控制云台，云台跟随外部自瞄命令。

松开右键后恢复鼠标手动控制。

## 6. 开火条件

### 6.1 人工操作模式

真正生成一颗 17 mm 弹丸必须同时满足：

```text
按住右键 RMB
      AND
按住左键 LMB
      AND
外部命令没有超时
      AND
外部自瞄 fire = true
      AND
发射冷却完成
            ↓
      生成实际 Projectile
```

因此：

```text
RMB = 是否启用外部自瞄
LMB = 操作手是否允许发射
fire = 自瞄算法是否认为当前适合开火
```

三者职责不同。

例如：

```text
RMB=true, LMB=true, fire=false
→ 云台由自瞄控制，但不发弹

RMB=true, LMB=false, fire=true
→ 自瞄认为可开火，但操作手未允许，因此不发弹

RMB=true, LMB=true, fire=true
→ 满足发射冷却后，实际生成 17 mm 弹丸
```

### 6.2 自动 Benchmark 模式

默认：

```toml
[operator]
benchmark_auto_hold_inputs = true
```

自动 Benchmark 会等价模拟：

```text
RMB = true
LMB = true
```

但是**不会替外部自瞄生成 `fire=true`**。

因此最终仍然需要：

```text
external fire = true
```

才能发弹。

这意味着 Benchmark 可以真实测试：

```text
Detector
Tracker
Predictor
Aimer
Planner
Shooter
```

整个开火链，而不是只测试瞄准角。

## 7. 云台角度坐标约定

当前仿真世界的零位：

```text
yaw   = 0°
pitch = 0°
```

枪管与相机朝向世界：

```text
-Z
```

### 7.1 Pitch

```text
pitch > 0
```

表示枪口向上。

```text
pitch < 0
```

表示枪口向下。

### 7.2 Yaw

Yaw 使用 Bevy 绕世界 `+Y` 轴的正旋转。

从初始朝向 `-Z` 看：

```text
yaw > 0
```

会转向：

```text
-X
```

如果你的真实下位机、自瞄项目或现有协议 yaw 正方向与此相反，建议在**适配层**中做：

```cpp
sim_yaw = -robot_yaw;
```

不要直接修改仿真世界内部坐标定义。

## 8. 接收相机画面

### 8.1 TCP 连接

仿真器默认在：

```text
127.0.0.1:39002
```

启动 TCP Server。

外部自瞄作为 TCP Client 连接。

连接建立后会连续收到：

```text
40 byte Header
JPEG Payload

40 byte Header
JPEG Payload

40 byte Header
JPEG Payload
...
```

### 8.2 40 字节帧头

所有整数均采用**网络字节序 / Big Endian**。

| Offset | 长度 | 类型 | 含义 |
|---:|---:|---|---|
| `0` | 8 | `char[8]` | Magic：`AIMSIM01` |
| `8` | 8 | `uint64` | `frame_id` |
| `16` | 8 | `uint64` | 相机采集时间戳 `timestamp_ns` |
| `24` | 4 | `uint32` | 图像宽度 |
| `28` | 4 | `uint32` | 图像高度 |
| `32` | 4 | `uint32` | JPEG 长度 |
| `36` | 4 | `uint32` | Reserved，目前为 0 |

总长度：

```text
40 bytes
```

Magic 必须为：

```text
AIMSIM01
```

随后读取 `jpeg_len` 个字节，即得到完整 JPEG 图片。

Python 对应格式：

```python
HEADER = struct.Struct("!8sQQIIII")
```

### 8.3 解码流程

```text
TCP recv_exact(40)
       ↓
解析 Header
       ↓
检查 magic == AIMSIM01
       ↓
读取 jpeg_len bytes
       ↓
JPEG Decode
       ↓
cv::Mat / numpy image
       ↓
Detector
```

必须使用类似 `recv_exact()` 的逻辑。

不要假定：

```cpp
recv(socket, buffer, 40, 0);
```

一次就一定拿到完整 40 字节。TCP 是字节流协议，单次读取可能只收到部分数据。

## 9. 相机内参

相机内参通过 Telemetry UDP 包发送。

字段：

```json
"camera_info": {
  "width": 1280,
  "height": 720,
  "fx": 1108.5,
  "fy": 1108.5,
  "cx": 640.0,
  "cy": 360.0
}
```

对应内参矩阵：

```text
      fx   0   cx
K =   0   fy   cy
      0    0    1
```

C++ 中可构造：

```cpp
cv::Mat camera_matrix = (cv::Mat_<double>(3, 3) <<
    fx, 0.0, cx,
    0.0, fy, cy,
    0.0, 0.0, 1.0);
```

当前核心相机模型为理想针孔相机。

当前版本没有额外畸变模型，因此可按：

```text
k1 = k2 = p1 = p2 = k3 = 0
```

处理。

## 11. 遥测字段说明

### 11.1 云台状态

```text
gimbal_yaw_deg
gimbal_pitch_deg
```

这是仿真中**当前实际云台角**。

它不一定瞬间等于你发送的 `yaw_deg / pitch_deg`，因为仿真器还有限速：

```toml
max_yaw_speed_dps = 720.0
max_pitch_speed_dps = 540.0
```

数据链：

```text
外部 target yaw/pitch
      ↓
云台限速执行
      ↓
actual gimbal yaw/pitch
```

这使 MPC / Planner 可以测试执行机构跟随行为。

### 11.2 操作与自瞄状态

`auto_aim_enabled`

表示当前是否启用了外部自瞄控制。人工模式下基本对应 RMB 是否按住。

`operator_trigger_held`

表示操作手是否允许开火。人工模式下基本对应 LMB 是否按住。

`external_fire_advice`

就是外部自瞄最后一次发送的：

```json
"fire": true
```

`external_command_fresh`

表示外部命令是否还在超时时间以内。如果程序挂掉、网络断开或者长时间没有发送，该值会变为 `false`，此时开火会被禁止。

## 12. 位姿数据

提供四组位姿：

```text
shooter_pose
gimbal_pose
muzzle_pose
camera_pose
```

格式统一：

```json
{
  "translation_m": [x, y, z],
  "quaternion_xyzw": [qx, qy, qz, qw]
}
```

注意四元数顺序是：

```text
[x, y, z, w]
```

不是：

```text
[w, x, y, z]
```

位置单位为 `m`，并且都是世界坐标系下的位姿。

## 13. 时间戳与时间对齐

相机帧包含：

```text
camera timestamp_ns
```

遥测包包含：

```text
telemetry timestamp_ns
```

两者都来自仿真主机的系统时钟：

```text
Unix/System Time
单位：ns
```

外部自瞄不要在接收后简单用本机接收时间替换仿真器提供的时间戳。

推荐数据流：

```text
Camera Frame
capture timestamp
      │
      ▼
图像队列
      │
      ├────────────┐
      │            │
Telemetry          │
timestamp          │
      │            │
      ▼            ▼
云台姿态历史缓存
      │
      ▼
按相机 timestamp 插值
      │
      ▼
image 对应 gimbal pose
      │
      ▼
Detector / PnP
```

这样才能正确测试：

```text
图像延迟
姿态时间对齐
PnP
Tracker
预测
```

## 14. 外部自瞄推荐软件结构

建议不要直接把 UDP/TCP 代码散落进 Detector / Tracker。

推荐：

```text
AimSimAdapter
│
├── CameraReceiver
│     ↓
│   ImageFrame
│
├── TelemetryReceiver
│     ↓
│   GimbalState / PoseHistory
│
└── CommandSender
      ↑
   AimCommand

        │
        ▼

AutoAim
│
├── Detector
├── PnP
├── CoordinateTransformer
├── Tracker
├── Predictor
├── Aimer
├── Planner
└── Shooter
```

统一定义：

```cpp
struct ImageFrame
{
  cv::Mat image;
  uint64_t frame_id;
  uint64_t timestamp_ns;
};

struct AimCommand
{
  double yaw_deg;
  double pitch_deg;
  bool fire;
};
```

这样仿真接口只存在于：

```text
AimSimAdapter
```

真实机器人上则替换成：

```text
Camera + CAN/Serial Adapter
```

算法本身不用因为仿真环境改变。

## 15. C++ 接入示例

### 15.1 命令结构

```cpp
struct AimCommand
{
  double yaw_deg;
  double pitch_deg;
  bool fire;
};
```

发送的 JSON：

```cpp
nlohmann::json j{
  {"yaw_deg", command.yaw_deg},
  {"pitch_deg", command.pitch_deg},
  {"fire", command.fire}
};
```

最终字符串：

```cpp
const std::string payload = j.dump();
```

通过 UDP 发送到：

```text
127.0.0.1:39000
```

### 15.2 推荐控制循环

```cpp
while (running) {
  const auto image = camera_receiver.latest();

  const auto pose =
    telemetry_buffer.interpolate(image.timestamp_ns);

  const auto detections = detector.detect(image.image);

  const auto observation =
    solver.solve(detections, pose);

  tracker.update(observation, image.timestamp_ns);

  const auto target = tracker.predict();

  const auto aim = aimer.solve(target);

  AimCommand command;
  command.yaw_deg = aim.yaw_deg;
  command.pitch_deg = aim.pitch_deg;
  command.fire = shooter.can_fire(target, aim);

  command_sender.send(command);
}
```

推荐另外维持一个固定频率命令发送线程，例如 `100 Hz CommandSender`。

即使主算法这一帧没有产生新的检测结果，也继续发送最新安全命令。

目标丢失时建议：

```json
{
  "yaw_deg": 0.0,
  "pitch_deg": 0.0,
  "fire": false
}
```

实际项目中可以把 yaw/pitch 保持为最近的安全目标角，但最重要的是：

```text
目标不可靠 → fire=false
```

## 17. 建议的正式联调顺序

### 第 1 阶段：只接相机

确认：

```text
TCP 连接正常
frame_id 连续增长
JPEG 解码正常
分辨率正确
```

此时不要发送控制命令。

### 第 2 阶段：接遥测

确认能够读取：

```text
gimbal_yaw_deg
gimbal_pitch_deg
camera_pose
camera_info
```

手动移动鼠标云台，检查外部程序中的 yaw/pitch 是否同步变化。

### 第 3 阶段：固定角度控制

外部程序持续发送：

```json
{
  "yaw_deg": 20.0,
  "pitch_deg": 0.0,
  "fire": false
}
```

按住右键，确认云台逐渐运动到：

```text
yaw ≈ 20°
```

然后测试：

```text
yaw = -20°
pitch = ±10°
```

重点检查 yaw 正负方向。

### 第 4 阶段：接 Detector + PnP

只输出 yaw / pitch，并始终：

```json
"fire": false
```

先做到能够稳定跟踪一块静止装甲板。

### 第 5 阶段：接 Tracker / Predictor

测试：

```text
RPM = 30
RPM = 60
RPM = 120
RPM = 180
```

观察：

```text
检测角
预测角
command yaw
actual yaw
```

是否合理。

### 第 6 阶段：接开火判断

实现 Planner / Shooter：

```text
fire=true/false
```

然后按住 RMB + LMB，开始测实际命中率和 DPS。

### 第 7 阶段：自动 Benchmark

确认人工模式正确后再启动：

```text
距离 × RPM × 平移速度
```

## 18. 常见问题

### 18.1 自瞄发送了 fire=true，但是不发弹

检查遥测：

```text
auto_aim_enabled
operator_trigger_held
external_fire_advice
external_command_fresh
```

人工模式必须同时为：

```text
auto_aim_enabled       = true
operator_trigger_held  = true
external_fire_advice   = true
external_command_fresh = true
```

即：

```text
RMB 按住
LMB 按住
fire=true
命令没有超时
```

### 18.2 自瞄能控制但方向反了

最常见是 yaw 符号定义不同。

可以在适配器中：

```cpp
command.yaw_deg = -solver_yaw_deg;
```

不要直接改 Tracker 或世界坐标系。

### 18.3 相机画面能收到，但偶尔协议错位

检查是否使用：

```text
recv_exact(40)
```

以及：

```text
recv_exact(jpeg_len)
```

TCP 不保证一次 `recv` 返回请求的全部字节。

### 18.4 仿真器突然不再执行自瞄命令

检查发送周期。

默认命令超时：

```text
350 ms
```

推荐以约：

```text
100 Hz
```

持续发送最新命令。

### 18.5 yaw/pitch 已经对准，但是命中率仍然低

这不一定是通信问题，还要检查：

```text
相机-枪口安装偏移
弹道重力补偿
子弹飞行时间
目标旋转预测
平移预测
云台执行机构延迟
fire 时机
```

仿真器的目的就是让这些误差最终通过：

```text
真实 17 mm Projectile → Armor collision
```

体现到命中率和 DPS 上。
